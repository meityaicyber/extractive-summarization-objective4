Following vulnerabilities have been discovered: The application performs inadequate validation of uploaded files, allowing attackers to bypass file type restrictions through manipulation of file signatures (magic bytes). By modifying the file header to resemble an allowed format, a malicious file was successfully uploaded despite containing unauthorized content.

The application is vulnerable to Vertical Privilege Escalation due to improper enforcement of server-side authorization controls. By using a valid authenticated session (including a swapped session cookie belonging to another Tech Support user), an attacker can create new privileged accounts, assign administrative roles, and obtain elevated access within the application. Successful exploitation may lead to complete compromise of the administrative interface, unauthorized modification of application configuration, creation of persistent administrator accounts, access to sensitive information, and loss of confidentiality, integrity, and availability of the platform. During testing, it was observed that a user with the Tech Support role possesses administrative capabilities equivalent to an Administrator, including the ability to create privileged accounts such as Administrator and CEO. Additionally, after replacing the authenticated session cookie with another valid Tech Support user's session, the application continued to authorize privileged administrative operations without performing sufficient authorization checks.

Implement strict server-side authorization checks for every privileged endpoint and validate user permissions independently of client-supplied data or session context. Ensure that sensitive operations such as user creation, role assignment, and privilege management are restricted exclusively to authorized administrative roles. Follow the principle of least privilege by assigning only the minimum permissions required for each role, conduct periodic RBAC reviews, and implement comprehensive audit logging for all privilege-related actions to detect and investigate unauthorized administrative activities. Implement anti-framing protections by configuring the X-Frame-Options response header with the value DENY or SAMEORIGIN, depending on business requirements.
