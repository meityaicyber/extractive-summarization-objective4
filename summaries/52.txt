The application exposes CAPTCHA values or validation data directly within the server response. An attacker can intercept the response and retrieve the CAPTCHA answer without solving the challenge manually, thereby bypassing the CAPTCHA protection mechanism. This weakness can enable automated attacks such as brute force attempts, account enumeration, spam submissions, or abuse of application functionalities intended to be protected against bots.

CAPTCHA values and validation logic should never be exposed in client-side responses, hidden fields, JavaScript variables, or API responses. CAPTCHA verification must be performed securely on the server side, where the generated challenge and expected answer are stored and validated internally. Implement secure session handling, short CAPTCHA expiration times, and rate limiting to further reduce the risk of automated abuse. Additionally, responses should only indicate whether CAPTCHA validation succeeded or failed without revealing any sensitive verification details.
