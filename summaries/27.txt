Cross-Site Scripting (XSS) via Unrestricted File Upload occurs when an application fails to properly validate the type, extension, and content of uploaded files. Weak or client-side-only validation lets an attacker bypass restrictions using a proxy tool and upload a file containing malicious HTML/JavaScript disguised as a legitimate file type. When the file is later accessed or previewed, the browser executes the embedded script instead of treating it as inert data, resulting in stored or reflected XSS. Application fails to properly validate the type, extension, and content of uploaded files, relying on weak or client-side-only validation.

Validate File Content: Implement server-side validation based on file signatures (magic bytes) and verified MIME types instead of relying solely on file extensions or client-provided Content-Type headers. Enforce an Allow-List: Restrict uploads to a predefined set of approved file types (e.g., .pdf, .jpg, .png) based on the application's business requirements and reject all unsupported formats by default. Serve Uploaded Files Securely: Configure uploaded files to be served using Content-Disposition: attachment and a safe Content-Type, such as application/octet-stream, to prevent browsers from rendering or executing potentially malicious content.
