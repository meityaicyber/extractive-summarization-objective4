As part of the Web Application Security Audit proposal, AKS IT’s Security Consultants conducted the security audit of the Supervisory Control and Data Acquisition(SCADA) web application from 01 May 2026 to 07 August 2026. A grey box assessment was performed to identify the vulnerabilities defined by the CERT-In Guidelines, NIC Guidelines, OWASP standard and other best practices. This is the final level of the web application security audit report, and it is observed that all the previously reported vulnerabilities are mitigated.

CAPTCHA Not Implemented. The application's architecture relies on a DOP (Socket) based communication mechanism for real-time data exchange, which prevents proper enforcement of CORS policies without disrupting existing functionality. The Content Security Policy (CSP) for the NMS SCADA Web Application is intentionally configured to retain the unsafe-inline and unsafe-eval directives, as removing these would significantly impact the application's structure, user interface rendering, and core functionality.

Implement proper session timeout mechanisms that are compatible with the existing socket-based communication architecture, ensuring that session expiration does not disrupt real-time data exchange. Reevaluate the CORS configuration to ensure it adheres to security best practices while maintaining application functionality, and consider removing unsafe-inline and unsafe-eval directives from the Content Security Policy to reduce XSS risk. Implement comprehensive input validation and sanitization mechanisms to prevent Cross-Site Scripting (XSS) attacks, and consider removing unsafe-inline and unsafe-eval directives from the Content Security Policy (CSP) while ensuring application functionality is not impacted.
