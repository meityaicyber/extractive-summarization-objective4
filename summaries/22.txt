It was observed that, during the initial assessment, a total of 2 vulnerabilities were identified. During the revalidation assessment, 1 finding was found to be remediated successfully, while 1 informational finding remains open. The findings are categorized in the table and chart below.

It was observed that Spring Boot Actuator endpoints on `connector-api` and `productprocess-api` are exposed without authentication. Sensitive endpoints including env, beans, health, configprops are accessible. The `heapdump` endpoint is also accessible and allows complete heap dumps to be downloaded from multiple services. An attacker can download heap dumps and extract sensitive information such as credentials API keys and session tokens. This can also provide detailed insight into application internals and increase the risk of unauthorized access. Spring Boot Actuator endpoints are exposed without authentication and unnecessary endpoints are not disabled in production environments. It was observed that the `appconfig.json` endpoint returns an unauthenticated response exposing the application's internal architecture, including API route templates, module names, and integration paths for services like Party Management and Comments. An attacker can use this information to understand the internal API structure and identify available endpoints.

It is recommended to restrict access to Spring Boot Actuator endpoints by enforcing authentication and authorization. Additionally, disable or limit exposure of unnecessary Actuator endpoints in production environments and ensure that only authorized users can access management interfaces. It is recommended to restrict access to configuration files and metadata endpoints to authorized users or internal systems. Sensitive internal details should not be publicly exposed. These files and endpoints should also be reviewed regularly to prevent unnecessary information exposure.
