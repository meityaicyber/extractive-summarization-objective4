CAPTCHA in Response occurs when an application exposes the CAPTCHA value or solution in HTTP responses, API outputs, or client-side code, allowing attackers to bypass the CAPTCHA validation mechanism.

Allows attackers to bypass the CAPTCHA validation mechanism by using the exposed CAPTCHA value or solution. The CAPTCHA value or solution is included in the server response, API output, or client-side code, enabling bypass of validation.

The enforcement mechanism(s) should deny all access by default, requiring explicit grants to specific users and roles for access to every page. Implementation of salted SHA-256 or salted SHA-512 hashing algorithms on password fields, while using plain SHA-256 or SHA-512 hashing on new password fields. If HTTP cookies are used for transmitting session tokens, then the secure flag should be set to prevent transmission over clear-text HTTP. At the code level, make it mandatory for developers to declare the access that is allowed for each resource, and deny access by default.
