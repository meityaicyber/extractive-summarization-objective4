As part of the Web Application Security Audit proposal, AKS IT’s Security Consultants conducted the security audit of the Network Management Server(NMS) web application from 04 May 2026 to 07 August 2026. A grey box assessment was performed to identify the vulnerabilities defined by the CERT-In Guidelines, NIC Guidelines, OWASP standard and other best practices. This is the final level of the web application security audit report, and it is observed that all the previously reported vulnerabilities are mitigated.

The client organization states that the use of a DOP (Socket) based communication mechanism for real-time data exchange prevents the enforcement of cookie attributes without disrupting existing socket communication and user session handling. The use of a DOP (Socket) based communication mechanism for real-time data exchange prevents the proper enforcement of cookie attributes and session management controls. The Content Security Policy (CSP) for the NMS SCADA Web Application is intentionally configured to retain the unsafe-inline and unsafe-eval directives, as removing these would significantly impact the application's structure, user interface rendering, and core functionality. The application is vulnerable to Cross-Site Scripting (XSS) attacks due to the presence of unsafe-inline and unsafe-eval directives in the Content Security Policy (CSP). The Content Security Policy (CSP) is intentionally configured to retain unsafe-inline and unsafe-eval directives to maintain application functionality, which introduces a security risk despite mitigation measures.

Implement a secure Content Security Policy (CSP) that removes unsafe-inline and unsafe-eval directives while ensuring application functionality is preserved through proper input validation and sanitization. Additionally, ensure all required security headers, including X-XSS-Protection, X-Frame-Options, and others to mitigate clickjacking and related web-based attacks, are implemented and regularly monitored.
